# CLAUDE.md

This file is read automatically by Claude Code at session start.

## Source of truth

**`SPEC.md` is the canonical requirements document.** Read it in full before
writing any code. Do not restate or reinterpret requirements from memory —
if `SPEC.md` and this file conflict, `SPEC.md` wins; flag the conflict and
stop rather than silently picking one.

This project is also worked on interchangeably with Codex (via `AGENTS.md`)
and Cursor (via `.cursor/rules/`). All three read the same `SPEC.md`. Do not
introduce Claude-Code-specific requirements or shortcuts that the other tools
wouldn't also follow — the deliverable must be tool-agnostic and reproducible
by anyone running the documented command.

## Planning

When asked to plan or scaffold a phase, use .agents/skills/orchestrate-phase-planner/SKILL.md.

## Workflow

Work phase-gated, matching `SPEC.md` §0 and §2:

`P0 Data Load/Validate → P1 Safety Gate → P2 Multimodal Ingestion → P3 Personalization/Retrieval → P4 Decision Fusion/Confidence → P5 Output Generation/Validation`

- Do not start a phase until the prior phase's REQ items are implemented and
  at least smoke-tested.
- Before implementing a phase, inspect the actual dataset files relevant to
  it (`view`/read the CSVs directly — don't assume schema from the README).
  Resolve the Open Questions in `SPEC.md` §6 as you go; update that section
  with findings.
- Each REQ ID should be traceable to a specific function/module — prefer
  naming that makes `grep REQ-P3-03` land you in the right place.
- If a requirement turns out to be ambiguous or wrong once real data is seen,
  don't quietly work around it — propose the SPEC.md edit, apply it, and
  continue. Log the change as a new ADR entry in SPEC.md §5.

## Testing

Build out `SPEC.md` §4's test taxonomy as each phase lands. For any test
category that doesn't apply to a given REQ (e.g. voice-specific tests on a
text-only phase), write the explicit N/A justification rather than omitting
the row.

Before finishing, run the self-validation against `dataset/sample_messages.csv`
required by REQ-P5-02 and report the agreement rate.

## Commit / PR hygiene

- Include AI co-author attribution in commit messages, but NOT in PR descriptions, or code comments,
  (no "Generated by Claude," no meta-commentary about the
  assistance process, no links to sessions). Write as if this is ordinary authored work.
- Ensure all commits follow a message naming convention of: 
  <:emoji/gitmoji: type(scope): imperative description> with accompanying bullets as needed.
- Commit messages should NOT reference REQ IDs where relevant (e.g.
  "Implement safety gate scam threshold — REQ-P1-02, REQ-P1-04").

## Transcript logging

Do not remove or weaken the transcript-logging behavior already defined in
`AGENTS.md` (appending session summaries to the platform-specific `log.txt`
path). That log is a required submission artifact per the README — treat it
as load-bearing, not optional boilerplate.

## Secrets

Read all API keys from environment variables. Never write a key into any
file in this repo, including scratch/debug scripts.
